Task artifacts and linking

PageSpace is the durable delivery record. An owner's implementation request authorizes routine discovery, planning, task administration, spawning, reviews and fixes within the requested outcome. Artifact creation is administration, not another permission gate. Planning-only requests remain planning-only.

Locations

  • Roadmap: epic, phase and task criteria and status. Issues holds defects or improvements no open slice owns.
  • Plans/<slice>: the one slice plan with its task list, which is also the delivery record a successor resumes from.
  • Prompts: the point guard's mission briefs and shared rules.
  • Reviews live on the PR as comments, in the format of docs/development/reviews.md.
  • Library: universal role prompts and reusable skills, including the existing Library/Agents and Library/Engineering Standards folders. These contain no task-specific back-links.

Current-work intake

Open Start here, then read Product intent/Product map, applicable capability intents and their "Constraints other features must respect now" sections. Follow affected-capability cross-links: Rooms/realtime to Spectating, Formats to Judging, Messaging to Privacy. Link these sources from the slice plan. Future intent constrains current work without creating a future task tree. Design work extends the existing shipped UI and canvases in Designs.

Archive/Work history remains a TASK_LIST. Preserve task/page IDs, direct-parent membership, criteria and statuses at move time; bun board:stale reconciliation still applies there.

Linking and ownership

Specific artifacts mention the general records they use: task Related pages mention the plan and the PR. Documents use page mentions; GitHub descriptions and comments use verified PageSpace URLs. Never upload credentials or environment secrets.

Builders create and claim in-scope tasks, keep their status and update the plan. Preserve delegated criteria and the requested outcome; scope cuts or changed product decisions go to the point guard on the channel. Building tasks are In Progress, and tasks of an open slice PR are In Review. A merge moves the PR's tasks to Done when its latest review verdict approves, otherwise to Merged. Builders never self-Done.

Findings

An in-scope finding is fixed in the slice PR. Anything outside the slice is filed as ISSUE-n in Issues, with origin, why, criteria and the PR linked, in the same session. A finding never lives only in a comment.
