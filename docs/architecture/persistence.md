# Persistence and ephemeral infrastructure

Platform/data owners maintain `@daisy/db`; application features call its public operation API. Drizzle and Bun SQL stay private. Tables are organized by record ownership; do not grow one giant schema file. Domain snapshots are serialized values, not database rows or ECS internals. The adapter stores a JSON snapshot plus searchable identity/resolution/format. Consumers validate loaded snapshots with the domain/protocol decoder before use. `createdBy` is nullable for service-originated architectural proofs; actual authenticated features provide an explicit user FK.

Identifiers are application-generated cuid2 values before writes (ADR 0018), shared across protocol/domain/persistence; PostgreSQL stores them as text and never generates them, and exactly one identifier shape is accepted anywhere (ADR 0023 withdrew the UUID carve-out). Timestamps use timestamptz and UTC ISO strings, durations use integer milliseconds. `createdAt` is immutable; mutations explicitly update `updatedAt`. Version begins at 1; `saveSnapshot` updates only the expected version and returns null on conflict. A retry re-reads current state and reruns domain rules. Do not blindly replay stale snapshots. Users referenced by debates cannot be deleted; privacy/deletion policy must be designed before adding identity data. Username normalization belongs in the future identity application operation.

`createDebate` runs within an explicit transaction. Future compound operations belong in focused adapter functions sharing one transaction, not a generic repository wrapper. Concurrency-sensitive operations must document transaction boundary, duplicate delivery, retry budget, stable command/idempotency key, and conflict behavior. Unique debate IDs already prevent duplicate creation; this is not complete idempotency (a duplicate may have different payload). Full idempotency needs a durable key plus payload digest and result in the same transaction; add that with the first real command consumer.

Redis is never authoritative for results, ballots, ratings or recordings metadata. Keys are `<deployment>:v1:<validated-segment>`; expiry is mandatory and set atomically with the value. Isolate deployments through namespace and credentials. Tests get unique namespaces and delete only their own keys. No global flush. Cache/presence loss must be recoverable from authoritative state. Rate limiting requires an atomic server-side operation and explicit outage policy before public mutations ship; in-memory limiters are not multi-instance enforcement.
