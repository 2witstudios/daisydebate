# Persistence and ephemeral infrastructure

Platform/data owners maintain `@daisy/db`; application features call its public operation API. Drizzle and Bun SQL stay private. Tables are organized by record ownership; do not grow one giant schema file. Domain snapshots are serialized values, not database rows or ECS internals. The adapter stores a JSON snapshot plus searchable identity/resolution/format and the lifecycle projections `mode`, `phase`, `visibility`, `started_at`, `completed_at`, `outcome` (ADR 0029). Consumers validate loaded snapshots with the domain/protocol decoder before use. `createdBy` references `actors`, never `users`, and is nullable for service-originated architectural proofs.

Identifiers are application-generated cuid2 values before writes (ADR 0018), shared across protocol/domain/persistence; PostgreSQL stores them as text and never generates them, and exactly one identifier shape is accepted anywhere (ADR 0023 withdrew the UUID carve-out). Timestamps use timestamptz and UTC ISO strings, durations use integer milliseconds. `createdAt` is immutable; mutations explicitly update `updatedAt`. Version begins at 1; `saveSnapshot` updates only the expected version and returns null on conflict. A retry re-reads current state and reruns domain rules. Do not blindly replay stale snapshots. Account deletion tombstones the user (ADR 0029): the row keeps its id, `deleted_at` is set and PII is scrubbed (`email`, `username`, `image` NULL, `name = ''`, enforced by CHECK); auth rows are deleted and active role grants revoked in the same transaction, while the user's actor and competitive history stay intact. Username normalization belongs in the future identity application operation.

`createDebate` runs within an explicit transaction. Future compound operations belong in focused adapter functions sharing one transaction, not a generic repository wrapper. Concurrency-sensitive operations must document transaction boundary, duplicate delivery, retry budget, stable command/idempotency key, and conflict behavior. Unique debate IDs already prevent duplicate creation; this is not complete idempotency (a duplicate may have different payload). Full idempotency needs a durable key plus payload digest and result in the same transaction; `debate_commands` is that table, and its writer lands with the first real command consumer.

Redis is never authoritative for results, ballots, ratings or recordings metadata. Keys are `<deployment>:v1:<validated-segment>`; expiry is mandatory and set atomically with the value. Isolate deployments through namespace and credentials. Tests get unique namespaces and delete only their own keys. No global flush. Cache/presence loss must be recoverable from authoritative state. Rate limiting requires an atomic server-side operation and explicit outage policy before public mutations ship; in-memory limiters are not multi-instance enforcement.

Authentication mail diagnostics live in `email_delivery`, `email_delivery_event` and `email_suppression` (ADR 0025): message and event IDs, a monotonic status rank and a keyed SHA3-256 recipient hash only — never an address or a provider payload. Rate-limit counters are Redis-only (`<namespace>:v1:rl:<sha3-256>`, one atomic Lua `EVAL`, always expiring).

## Competitive tables (ADR 0029)

One schema file per ownership area under `packages/db/src/schema/`. Every status column is `text` plus `CHECK`, every id is an app-minted cuid2, every mutable row carries `version > 0`, and every CHECK vocabulary that has a protocol counterpart (`debateRoles`, `phaseSchema`) is built from it.

| Table                 | Owner         | Holds                                                                                                                                                                                   | Deletion                                                          |
| --------------------- | ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| `actors`              | identity      | Competitive identity: `kind` (`human`), one `user_id` per human actor; no PII                                                                                                           | `RESTRICT` from `users`; never deleted                            |
| `formats`             | platform/data | Slug id, `rules` jsonb validated by `formatRulesSchema` (exhaustive `seats`, millisecond `clock`), `ranked_eligible`; seeded by `scripts/seed.ts`                                       | `RESTRICT` from `debates`, `ratings`, `rating_changes`            |
| `debates`             | domain        | Snapshot (source of truth) plus projections `mode`, `phase`, `visibility`, `started_at`, `completed_at`, `outcome` under `debates_lifecycle_check`; `created_by` → `actors`             | Cascades to participants, commands, ballots; `RESTRICT` by ledger |
| `debate_participants` | domain        | One row per seat `(role, slot)` for every role incl. judges; `status`; unique seat and unique actor per debate; no result column                                                        | `CASCADE` from `debates`                                          |
| `debate_commands`     | domain        | Idempotency and audit keyed by protocol `command_id`: SHA3-256 `payload_digest`, `result`, `resulting_version`, exactly one of `actor_id`/`service_id`                                  | `CASCADE` from `debates`                                          |
| `ballots`             | judging       | One per judge seat (`participant_id` unique): `decision`, `scores`, `reason`, `status`; voiding fields set iff `voided`                                                                 | `CASCADE` from `debates` and participants                         |
| `seasons`             | ratings       | Rating seasons; at most one `active` (partial unique index)                                                                                                                             | `RESTRICT` from ratings                                           |
| `ratings`             | ratings       | Current Glicko-2 `rating`/`deviation`/`volatility` per `(actor, format, season)`, projection of the ledger; leaderboard index `(format, season, rating DESC)`; nothing derivable stored | `RESTRICT` everywhere                                             |
| `rating_changes`      | ratings       | Append-only ledger: before/after triples, `calculation_version`, `occurred_at`; one row per `(debate, actor)`                                                                           | `RESTRICT` everywhere                                             |
| `role_grants`         | identity      | `admin`/`moderator`/`judge` grants to `users` with `scope_type` (`global`), `granted_by`, `granted_at`, `revoked_at`; one active grant per scope (partial unique index)                 | `RESTRICT` from `users`                                           |
